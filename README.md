## 1. Project Overview

This project investigates language modeling, word embeddings, and learned text representations through three experiments:

- **Part I – Language Model Comparison:** Train and compare N-gram, RNN, LSTM, and Transformer language models on a common corpus.
- **Part II – Embedding Variants and Ablation:** Investigate how randomly initialized, self-trained CBOW, and publicly pretrained GloVe embeddings affect LSTM language modeling performance.
- **Part III – Downstream Representation Analysis:** Evaluate representations extracted from the trained LSTM models on IMDb sentiment classification.

The main research objective is to understand how model architectures and embedding strategies affect next-token prediction and whether better language modeling performance translates into better downstream classification performance.

## 4. Datasets

### 4.1 WikiText-2

**Used in:** Part I and Part II

Dataset: [WikiText-2](https://huggingface.co/datasets/Salesforce/wikitext)

WikiText-2 is an English text corpus used for training and evaluating language models.

The same training, validation, and test splits are used for the language model comparisons.

Preprocessing includes:

1. Converting text to lowercase.
2. Tokenizing text using regular expressions.
3. Building a vocabulary from the training corpus.
4. Mapping tokens to integer IDs.
5. Handling unknown words using `<unk>`.
6. Handling sequence boundaries and padding.
7. Constructing input-target sequences for next-token prediction.

The vocabulary is constructed using training data only to avoid data leakage.

### 4.2 IMDb Movie Reviews

**Used in:** Part III

Dataset: [IMDb](https://huggingface.co/datasets/stanfordnlp/imdb)

IMDb contains movie reviews labeled as:

- `0`: Negative
- `1`: Positive

A balanced subset is used to reduce computational cost.


| Split      | Samples |
| ---------- | ------- |
| Training   | 5,000   |
| Validation | 1,000   |
| Testing    | 2,000   |


The training and validation subsets are created from the official IMDb training split. The official test split is used exclusively for final evaluation.

Preprocessing includes:

1. Applying the tokenizer from Part I.
2. Reusing the WikiText-2 vocabulary and token-to-ID mapping.
3. Replacing out-of-vocabulary words with `<unk>`.
4. Truncating reviews to a maximum of 128 tokens.
5. Applying dynamic padding within each batch.

The language models are not retrained on IMDb.

All models are trained and evaluated using the same WikiText-2 corpus.

The neural language models use randomly initialized, trainable input embeddings.

## 6. Part II: Embedding Variants and Ablation

Part II uses the LSTM architecture from Part I to investigate the effects of different input embeddings.

Three embedding configurations are compared:


| Variant | Initialization               | Trainable during LM training |
| ------- | ---------------------------- | ---------------------------- |
| Random  | Random initialization        | Yes                          |
| CBOW    | Self-trained on WikiText-2   | No                           |
| GloVe   | Public pretrained embeddings | No                           |


All three variants use the same embedding dimension, LSTM architecture, language modeling dataset, and training procedure.

### 6.1 Random Embeddings

The randomly initialized, trainable LSTM embeddings from Part I are reused as the baseline.

### 6.2 Self-trained CBOW Embeddings

A Continuous Bag-of-Words (CBOW) model is trained separately on the WikiText-2 training corpus.

Configuration:

- Embedding dimension: 100
- Context window size: 2
- CBOW batch size: 512
- CBOW epochs: 5
- Optimizer: Adam
- Learning rate: 0.001

CBOW predicts a target word using the average embeddings of surrounding context words.

After training, the input embedding matrix is extracted and loaded into a newly initialized LSTM.

The entire input embedding matrix is frozen during subsequent language model training.

CBOW pretraining time is measured separately from LSTM training time.

### 6.3 Pretrained GloVe Embeddings

Public pretrained GloVe embeddings are loaded using Gensim:

```python
import gensim.downloader as api

glove = api.load("glove-wiki-gigaword-100")
```

The embedding dimension is 100.

GloVe vectors are aligned with the WikiText-2 vocabulary.

Words not covered by GloVe are initialized using a normal distribution:


E_{\text{missing}}\sim N(0,0.02^2)


Padding embeddings are initialized to zero.

The complete embedding table, including missing-word vectors, remains frozen during language model training.

Vocabulary coverage is measured and reported.

### Part II Evaluation

The three LSTM variants are compared using:

- Test loss and perplexity.
- Training and validation convergence.
- Training stability.
- Language model training time.
- Representative generated text.
- Vocabulary coverage.
- Separate CBOW pretraining cost.

The analysis considers both embedding trainability and differences in the amount of data used for embedding pretraining.

## 7. Part III: Downstream Representation Analysis

Part III evaluates whether the learned LSTM representations are useful for sentiment classification.

### Task

Binary sentiment classification on IMDb movie reviews.

### Representation Extraction

Three trained LSTM models are reused:

- Random Embedding LSTM.
- Frozen CBOW Embedding LSTM.
- Frozen GloVe Embedding LSTM.

All language models are frozen during representation extraction.

For each review, token-level LSTM hidden states are obtained.

Mean pooling over valid tokens produces a fixed-length representation:


z=\frac{1}{L}\sum_{t=1}^{L}h_t


where:

- h_t is the LSTM hidden state at position t.
- L is the number of valid tokens, excluding padding.
- z is the resulting 256-dimensional text representation.

Padding tokens are excluded from the pooling operation.

### Classifier

A simple linear classifier is trained separately on each representation type:

```python
nn.Linear(256, 2)
```

All classifiers use the same architecture and training procedure.


| Hyperparameter  | Value         |
| --------------- | ------------- |
| Input dimension | 256           |
| Output classes  | 2             |
| Batch size      | 64            |
| Epochs          | 20            |
| Learning rate   | 0.001         |
| Optimizer       | Adam          |
| Loss function   | Cross-Entropy |


The checkpoint with the lowest validation loss is selected for evaluation.

### Evaluation

The downstream models are compared using:

- Test accuracy.
- Macro-F1 score.
- Confusion matrices.
- Representative classification errors.

The results are also compared against Part II language modeling perplexity to investigate whether better next-token prediction corresponds to better downstream classification performance.

## 10. Limitations

Several limitations should be considered when interpreting the results:

1. **Limited training corpus:** WikiText-2 is relatively small for training neural language models from scratch.
2. **Embedding coverage:** Some WikiText-2 vocabulary entries are not covered by pretrained GloVe embeddings.
3. **Pretraining differences:** GloVe benefits from external training data, so performance differences cannot be attributed solely to whether embeddings are frozen.
4. **Input truncation:** IMDb reviews are truncated to 128 tokens, potentially removing important sentiment information.
5. **Frozen representations:** The downstream classifiers use fixed LSTM representations without task-specific language model fine-tuning.
6. **Computational constraints:** Model sizes, dataset subsets, and training budgets are limited to keep the experiments computationally manageable.
